Design rationale

  • This draft starts from "Round 1, updated after research" and keeps its research-driven changes. The new changes come from the Mural design review, not from research findings. Link them to round 1 findings where they exist before using this draft in research.
  • Moving data quality onto its own page avoids sideways scrolling, but it separates data quality from the figures it affects. The team needs to decide if that's acceptable.
  • Replacing the View button with a link on the movement ID changes something round 1 participants used. Watch for this in round 2.

Defra branding

Based on the Defra branding guidance, limited to what Power BI can do. In Power BI this would be a report theme file (font, colours and text styles), an image visual for the logo and shapes for the header.

  • Defra green (#00A33B) has a contrast ratio of about 3.3:1 against white. That's enough for lines and borders (3:1), but not for normal-sized text (4.5:1), so it is only used for lines.
  • Data colours stay on the Analysis Function palette. Green would clash with the green status colour.
  • Power BI blue is still used for buttons, selection and focus outlines.

Questions for the team

  • Do Defra or the regulators already have a Power BI theme or report template we should use instead?
  • Whose logo should the header show? Users are likely to include staff from the Environment Agency, SEPA, Natural Resources Wales and NIEA.
  • Who should the contact at the bottom of each page be?

To check with a Power BI developer

  • Whether an image can be marked as decorative, so screen readers ignore the logo crest. For now it has the alt text "Department for Environment, Food and Rural Affairs".
  • Codes such as EWC codes and permit numbers still use a monospaced font (Consolas). Decide whether to keep it or use Arial.
  • The top navigation would be a page navigator (buttons). Site detail and Movements stay visible in it, so opened directly they show unfiltered or blank data. The empty state needs a measure that checks whether 1 site is selected. Check whether Power BI's own page list can be hidden where the report is published, so users don't see 2 sets of navigation.
  • The breadcrumb line would be text and buttons, as Power BI has no breadcrumb visual. Check that keyboard focus reaches the navigation first and that screen readers announce the current page.
  • Research question: do regulators who use other Power BI reports expect the standard bottom tabs?
  • Cells that stack 2 or 3 values need a matrix or a combined text measure.

Not changed yet

  • Some details are still only on hover (WCAG 1.4.13): chart column totals, some card explanations and EWC names in the Movements list.
  • Filters apply to every page (synced slicers in Power BI). This is unusual and may confuse users. Research question: do users notice and understand that filters carry across pages?
  • The box that appears when 1 site matches the filters is odd and needs rethinking.
  • Power BI controls the focus outline on its own visuals, so the yellow focus style only applies to custom buttons.
  • Absolute and mirror hazardous are both orange, and only the badge text tells them apart.
  • Site detail chart colours reuse the hazardous orange and POPs pink for ordinary EWC codes.
